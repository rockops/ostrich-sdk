# Test Plan: Docker Runner (operations.py)

## Objective
Verify the robustness and correctness of the `operations.container` function in `src/src/operations.py`, which is responsible for executing template operations within Docker or Podman containers.

## Testing Strategy
We will use **Unit Testing with Mocking** effectively. By mocking `subprocess.run` and `shutil.which` (or similar checks), we can inspect the exact command lists generated by the function without requiring a running Docker daemon or creating actual containers. This ensures tests are fast, deterministic, and environment-independent.

Tests will be written using `pytest` and `unittest.mock`.

## Test Cases

### 1. Basic Execution Flow
- **TC01: Simple String Command**
    - **Input**: `command: "echo hello"`, `runner.kind: docker`, standard params.
    - **Expected**: `docker run ... --entrypoint ... <image> sh -c "echo hello"`

### 2. Command Argument Handling
- **TC02: List Command Arguments**
    - **Input**: `command: { cmd: ["ls", "-la"] }`
    - **Expected**: `docker run ... <image> ls -la` (Arguments appended directly)
- **TC03: Map (Dict) Command Arguments**
    - **Input**: `command: { cmd: {"-n": "5", "--flag": null} }`
    - **Expected**: `docker run ... <image> -n 5 --flag` (Key-value pairs flattened, None values imply flag only) *Note: Current implementation needs verification/fix for this.*

### 3. Configuration Overrides
- **TC04: Image Override**
    - **Input**: Global `runner.image: default_img`, Command `image: custom_img`.
    - **Expected**: Command uses `custom_img`.
- **TC05: Entrypoint Override**
    - **Input**: Global `runner.entrypoint: /bin/sh`, Command `entrypoint: /app/run`.
    - **Expected**: Docker command includes `--entrypoint /app/run`.

### 4. Runtime Specifics
- **TC06: Podman specific flags**
    - **Input**: `params.runtime: podman`.
    - **Expected**: Command includes `--userns=keep-id` and avoids `--user uid:gid`.
- **TC07: Docker specific flags**
    - **Input**: `params.runtime: docker`.
    - **Expected**: Command includes `--user <uid>:<gid>`.

### 5. Environment & Volumes
- **TC08: Environment Variable Injection**
    - **Input**: `env: { MY_VAR: "value" }`.
    - **Expected**: Command includes `-e MY_VAR=value`, plus standard ostrich vars (`LOGLEVEL`, `DRYRUN`, etc.).
- **TC09: Volume Mounts**
    - **Expected**: Command includes mounts for `tmpdir` and `location` (current working dir) mapped to themselves.

### 6. Error Handling
- **TC10: Missing Image**
    - **Input**: No image defined in global runner or specific command.
    - **Expected**: `OstrichException("No container image defined...")`
- **TC11: Runtime Missing**
    - **Input**: `subprocess.run` raises `FileNotFoundError`.
    - **Expected**: `OstrichException("Container runtime ... not available")`
- **TC12: Execution Failure**
    - **Input**: Command returns non-zero exit code.
    - **Expected**: `OstrichException` containing error details.

## Implementation Plan
1. Create a test file `src/src/test/test_operations_runner.py`.
2. Implement a `MockParams` class to simulate `util.Params`.
3. Use `@patch("src.src.operations.run")` to capture calls.
4. Implement test methods corresponding to the cases above.
